# 澄川学院机务台

公共机房报修系统。学生、管理员、维修人员从不同入口登录，权限分开。学生提交机房、设备和故障描述；管理员选择 DeepSeek 或智谱做分诊，两次结果都保留；管理员确认后才能派发；维修人员接单、处理、完成。工单状态写在时间线上。

## 本地运行

```bash
npm install
cp .env.example .env.local
npm run dev
```

浏览器打开 [http://127.0.0.1:3847](http://127.0.0.1:3847)。

密钥只放在 `.env.local` 或服务器环境变量里，页面没有密钥输入框。

```bash
DEEPSEEK_API_KEY=
ZHIPU_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
ZHIPU_MODEL=glm-4-flash-250414
```

## 划分依据

五类标签和紧急程度写在 `lib/taxonomy.ts`，管理页「划分依据」展示同一份内容。模型提示词由这份依据生成。

| 标签 | 岗位 |
| --- | --- |
| 计算机主机 | 主机维修岗 |
| 显示设备 | 显示维修岗 |
| 网络设备 | 网络维修岗 |
| 投影与多媒体 | 多媒体维修岗 |
| 外设 | 外设维修岗 |

紧急程度按特急、紧急、较急、一般的顺序匹配。特急只用于安全风险，或整间主要功能全部不可用。

## 测试集

`data/cases.ts` 有 120 条机房场景模拟报修，每条包含机房、设备、故障描述、标签、紧急程度、岗位和依据。

```bash
npm test
npm run eval
```

`npm run eval` 会真实调用 DeepSeek 和智谱。缺少密钥时脚本直接退出，不写统计文件。全部调用结束后，结果写入 `data/eval-report.json`。管理页「测试统计」按逐条结果计算准确率、失败案例和两模型不一致案例，不使用预置百分比。

中断后再次运行会从 `data/eval-progress.json` 继续，避免把已完成的调用丢掉。
